## Executive Summary

`src/types.ts` currently exports 38 shared types and interfaces covering auth, users, CMS content, documents, media, carousel, external services, events, navigation, dashboard metrics, integrations, visitor stats, public snapshots, display settings, homepage settings, and site settings.

The file is structurally broad, but it should not be split in one pass. Many exports are backend-mirrored API contracts used by `src/services/googleApi.ts`, public pages, admin pages, service caches, and tests. Moving those contracts too early would create high import churn without reducing runtime risk.

Full P5 should not proceed yet. The first implementation should be a very small type-only PR for either public documents or site-view/visitor stats types, with a temporary re-export from `src/types.ts` if needed. API contract and public-home snapshot types should wait until `googleApi.ts` ownership is mapped.

## Types Not To Move Yet

Do not move these in the first implementation PR:

- `ContentItem`, `ContentStatus`, `ContentType`: high-churn, shared by public and admin, mirrored by `CONTENT_HEADERS`.
- `MediaAsset`, `MediaType`: shared by public rendering, admin media, content editor, carousel, and `googleApi.ts`.

## Recommended Migration Sequence

### P5.0 Audit Only

Complete this document. Do not move types.

### P5.1 Shared Types Re-Export Only

If useful, create `src/shared/types/index.ts` as a re-export-only facade from `src/types.ts`.

This should not move definitions. It only gives future feature modules a neutral import path and lets one PR prove that the project can tolerate type import churn without runtime changes.

### P5.2 Move Low-Risk Feature-Local Types First

Move one small group only. Candidate groups:

- `PublicDocumentItem` and `PublicDocumentListSnapshot`.
- Or `VisitorStatsSettings`.

Keep `src/types.ts` as a temporary re-export during the first implementation PR.

### P5.3 Move Public Documents Types

Target `src/features/public-documents/types.ts`.

Move `PublicDocumentItem` and `PublicDocumentListSnapshot` first. Consider `DocumentStatus` and `CmsDocumentItem` only in a separate admin-documents PR.

### P5.4 Move Site-View / Visitor Stats Types

Target either:

- `src/features/visitor-stats/types.ts` for `VisitorStatsSettings`.
- Or `src/features/site-view/types.ts` if the team wants visitor stats and site-view ownership together.

Prefer `visitor-stats` naming because the type is used by settings and display, not by the browser tracker payload.

### P5.5 Move Settings/Admin/Content Types Later

Do not move settings, content, media, auth, or snapshot types until smaller moves prove the pattern.

### P5.6 Move API Contract Types Only After `googleApi.ts` Ownership Is Mapped

Snapshot and API response contracts should wait until the project decides whether `googleApi.ts` remains a monolithic adapter or gets split into shared transport plus feature API wrappers.

## Safety Rules For Future P5 Implementation

- Move one type group per PR.
- Keep each PR type-only.
- Do not change runtime code behavior.
- Do not change API response shapes.
- Do not change Apps Script behavior or schema.
- Do not change cache behavior.
- Do not mix `googleApi.ts` refactors with type moves.
- Update tests only for import paths.
- Keep temporary re-export shims when they reduce churn.
- Remove shims only after repo-wide searches prove no old imports remain.
- Run `pnpm quality` after each phase.

## Risk Analysis

- High risk: API contract types, especially snapshots and contracts imported by `googleApi.ts`.
- High risk: `ContentItem`, because it touches public content, homepage sections, admin content editing, cache helpers, search, and tests.
- High churn: `MediaAsset`, because it spans content rendering, admin media, carousel, and uploads.
- Medium risk: public-home snapshot types, because `PublicHomeSnapshot` aggregates many domains.
- Medium risk: settings types, because site/homepage/display settings cross public shell, homepage, admin settings, normalizers, and Apps Script defaults.
- Low-medium risk: public-documents types after P4, because feature UI/cache ownership already exists.
- Low-medium risk: `VisitorStatsSettings` after P1/P3, because backend logic and frontend tracker are already separated.

## Decision

Do not start full P5 yet.

First safe implementation candidate:

- `PublicDocumentItem` and `PublicDocumentListSnapshot` into `src/features/public-documents/types.ts`.

Second safe implementation candidate:

- `VisitorStatsSettings` into `src/features/visitor-stats/types.ts` or `src/features/site-view/types.ts`.

Defer:

- `ContentItem`, `MediaAsset`, settings types, auth/session/user types, `CmsSnapshot`, `PublicHomeSnapshot`, and other public API snapshot contracts.
