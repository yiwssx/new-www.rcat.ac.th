# v3.3.2 Release Baseline

Status: **PREPARED / NOT YET RELEASED**

Planned release: `v3.3.2 — Content Editor Performance`

Integration branch: `integration/v3.3.2-content-editor-performance`

Prepared from integration commit: `b5afbdf29c25a7492f58515790a9f47a3dbc1805`

This document records the prepared v3.3.2 Content Editor Performance release baseline. It is intentionally pre-release evidence until the final integration commit reaches `main`, production verification succeeds, and the release tag is created.

## Included scope

- Nested lazy boundary for the rich-text editor runtime behind the existing lazy Content Editor dialog.
- Explicit Tiptap extension composition replacing the broad StarterKit dependency while retaining current editor behavior.
- Deferred advanced rich-text capability mode for advanced structures such as tables and horizontal rules.
- Deferred rich-text media picker loading until media insertion is requested.
- Editor-intent preload that starts the dialog shell and rich-text runtime together without preloading the editor on the initial Admin content list.
- Command-level editor parity coverage and unchanged `RCAT_BLOCKS_V1` round-trip coverage.
- Admin editor bundle-size governance and Tiptap/ProseMirror dependency-graph isolation governance.

Additional verified invariants:

- advanced optional-content runtime is deferred from the default first-open graph;
- rich-text media picker is deferred from the default first-open graph;
- public synchronous graph contains no Tiptap/ProseMirror modules;
- initial `/admin/content` graph contains no Tiptap/ProseMirror modules;
- Admin editor bundle result: PASS;
- editor dependency isolation result: PASS.

The current hard gates are:

- largest first-open editor-specific chunk must remain below 400,000 raw bytes;
- aggregate first-editor-open incremental JavaScript must remain at or below 138,000 gzip bytes;
- Tiptap/ProseMirror must remain absent from the public synchronous graph and initial `/admin/content` graph.
