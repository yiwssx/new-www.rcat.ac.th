# v3.3.2 Editor Dependency Graph Isolation

Task 8 makes the editor isolation targets executable release gates. It does not change editor behavior, saved content, Worker/API contracts, D1 schema, or production data.

## Protected graphs

The production Vite build is inspected at module-association level. The guard rejects `@tiptap/*` and `prosemirror-*` modules in either protected graph:

1. **Public synchronous graph** — the JavaScript files reachable through static imports from the `index.html` entry. Dynamic editor chunks are intentionally excluded.
2. **Initial `/admin/content` graph** — the static chunk closure that owns `src/admin/pages/ContentPage.tsx`, before create/edit intent loads `ContentEditorDialog` and the rich-text runtime.

The same in-memory production build used by `pnpm editor:bundle:check` supplies both the byte measurements from Task 7 and the dependency-isolation evidence from Task 8. This avoids a second production build in Governance.

## Fail-closed behavior

The isolation analyzer fails closed when a protected emitted chunk is missing or has no Vite module associations. Module IDs are normalized across Windows and POSIX separators before matching.

Forbidden runtime patterns:

- `/node_modules/@tiptap/`
- `/node_modules/prosemirror-`

These patterns cover Tiptap packages including `@tiptap/pm` and the underlying ProseMirror package family.

## Evidence

- `scripts/editor-dependency-isolation.mjs` — pure graph/module analyzer and report formatting.
- `scripts/editor-dependency-isolation.test.mjs` — normalization, graph collection, pass and leak fixtures.
- `scripts/check-admin-editor-bundle.mjs` — production-build integration; bundle and isolation gates share one Vite build.
- CI Governance runs `pnpm editor:bundle:check` and therefore hard-fails either a bundle-budget regression or an editor-runtime isolation regression.

Task 8 is accepted only when the full repository CI passes from the same PR head.
